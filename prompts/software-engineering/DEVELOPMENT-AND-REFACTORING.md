# 🛠️ 代码开发与重构

此提示词集专注于编码阶段、代码质量提升以及架构层面的优化。

## 高质量代码开发

### 提示词模板
```
请作为资深开发工程师，帮我实现以下功能：

功能描述：
[详细描述要实现的功能]

上下文信息：
- 技术栈：[如：React, TypeScript, Tailwind]
- 现有代码片段（如有）：
[插入相关代码]

开发要求：
1. 代码质量：遵循 DRY, KISS, SOLID 原则。
2. 类型安全：使用严格的类型定义（如果是 TS/Go 等）。
3. 异常处理：包含必要的错误捕获和边界处理。
4. 可测试性：代码应易于进行单元测试。
5. 性能考虑：避免明显的性能陷阱。

请提供完整的实现代码，并附带关键逻辑的解释。
```

## 代码审查 (Code Review)

### 提示词模板
```
请作为技术主管，对以下代码进行深度审查：

代码片段：
[粘贴待审查的代码]

审查维度：
1. 逻辑正确性：是否存在潜在的 Bug 或边界情况未处理？
2. 代码规范：是否符合行业标准，命名是否清晰？
3. 安全性：是否存在注入风险、信息泄露或鉴权漏洞？
4. 性能优化：是否有冗余计算、内存泄漏或慢查询？
5. 可维护性：代码是否过于复杂，是否有过度设计的嫌疑？

请给出具体的改进建议，并根据严重程度（High/Medium/Low）进行分类。
```

## 遗留代码重构

### 提示词模板
```
我有一段需要重构的旧代码，请帮我制定重构方案：

代码现状：
[粘贴旧代码]

重构目标：
- [如：提高可读性 / 将 Class 组件转为 Hooks / 拆分巨大的函数]

重构要求：
1. 渐进式：重构过程应尽量不破坏现有功能。
2. 模式应用：建议使用哪些设计模式（如：策略模式、工厂模式）来解耦？
3. 单元测试补全：为重构后的代码建议测试用例。

请提供重构后的代码，并解释主要的重构动作和收益。
```

## 性能优化建议

### 提示词模板
```
我的代码/系统目前面临性能瓶颈，请帮我分析并优化：

现象描述：
[描述具体的性能问题，如：首页加载慢、API 响应时间超过 2s]

相关环境/代码：
[提供相关的代码片段或系统配置]

分析要求：
1. 瓶颈定位：分析可能导致问题的环节（CPU 密集、I/O 阻塞、网络延迟、数据库索引）。
2. 短期修复：能够立即见效的应急方案。
3. 长期优化：根治问题的架构调整方案。
4. 监控指标：建议关注哪些性能指标以防止复发。

请给出分层级的优化策略。
```

## 使用技巧

1. **分段提供代码**：如果代码量很大，建议分模块提供，否则 AI 可能丢失细节。
2. **说明技术版本**：比如 "React 18" 或 "Python 3.11"，因为不同版本的最佳实践差异巨大。
3. **结合 Linter 结果**：可以把报错信息也喂给 AI，它修复的效果会更好。
