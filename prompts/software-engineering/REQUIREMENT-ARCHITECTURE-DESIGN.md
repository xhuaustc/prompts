# 💻 需求分析与架构设计

这是一个专注于软件工程初期的提示词集，涵盖从原始想法到详细架构设计的全过程。

## 需求深度分析

### 提示词模板
```
请作为资深产品专家和需求分析师，帮我分析以下产品创意：

项目基本信息：
- 项目名称：[名称]
- 核心目标：[一句话描述要解决什么问题]
- 目标用户：[谁会使用这个产品]

分析要求：
1. 用户故事 (User Stories)：请提供5-10个核心用户故事，采用 "作为... 我想要... 以便..." 的格式。
2. 功能需求 (Functional Requirements)：
   - 核心功能（MVP必须包含的）
   - 进阶功能（后续迭代考虑）
3. 非功能需求 (Non-Functional Requirements)：
   - 性能要求（响应时间、并发量等）
   - 安全性要求
   - 可靠性与可用性
4. 业务逻辑图描述：描述核心业务的流转过程。
5. 潜在风险分析：列出技术或业务上的潜在坑点。

请以专业、结构化的方式输出。
```

## 全局架构设计

### 提示词模板
```
请作为资深软件架构师，基于以下需求为我设计系统架构：

需求背景：
[在此处输入需求分析的结果或简述项目需求]

设计要求：
1. 总体架构风格：(如：微服务、单体、无服务器、事件驱动等) 并说明理由。
2. 技术栈建议：
   - 前端 (Web/App/小程序)
   - 后端 (语言/框架)
   - 数据库 (关系型/NoSQL/缓存)
   - 基础设施 (云服务/容器化/CI/CD)
3. 核心组件说明：描述系统中各个主要模块及其职责。
4. 数据流向图描述：用户请求是如何在系统中流动的。
5. 关键设计模式：建议采用哪些设计模式来解决特定问题。
6. 可扩展性与高可用方案：如何应对未来的用户增长。

请提供详细的架构方案，并给出决策理由。
```

## 数据建模与 API 设计

### 提示词模板
```
请帮我完成该系统的数据模型和 API 设计：

项目背景：
[项目简述]

设计要求：
1. 核心实体模型 (ER)：
   - 列出主要的表/集合及其字段
   - 描述实体间的关联关系 (1:1, 1:N, N:M)
2. API 设计 (RESTful)：
   - 提供核心业务流程所需的 API 端点
   - 包含：方法 (GET/POST/...)、路径、关键参数、返回示例
3. 数据库选型策略：针对不同的数据类型建议使用的存储引擎。
4. 数据安全建议：如脱敏、加密、审计等。

请确保设计符合最佳实践，且易于扩展。
```

## 技术选型对比与决策

### 提示词模板
```
我需要在以下几个技术方案中做决策，请帮我进行深度对比分析：

待对比方案：
- 方案 A: [如：使用 PostgreSQL]
- 方案 B: [如：使用 MongoDB]

项目上下文：
- 数据量级：[预估数据量]
- 并发要求：[预估并发]
- 团队背景：[团队技术栈偏好]
- 交付周期：[紧急程度]

请提供：
1. 维度对比 (性能、开发效率、运维成本、社区生态、学习曲线)
2. 各方案的优缺点 (Pros & Cons)
3. 针对本项目的具体建议
4. 迁移或演进路径建议
```

## 使用技巧

1. **从抽象到具体**：建议先运行“需求深度分析”，拿到结果后再运行“全局架构设计”。
2. **提供足够的上下文**：AI 对项目的背景了解越多，给出的架构方案就越具落地价值。
3. **质疑与迭代**：对于 AI 给出的架构决策，可以多问一句“为什么要选这个而不是 X？”，这能帮助你发现潜在的设计盲点。
4. **关注非功能需求**：在架构设计中，非功能需求（高并发、高可用）往往比功能实现更具挑战性。

## 相关工具

- **Mermaid.js**：可以使用 AI 生成 Mermaid 代码来绘制架构图。
- **Draw.io / Excalidraw**：用于手动绘制更精细的图纸。
- **Swagger / OpenAPI**：用于 API 文档标准化。
