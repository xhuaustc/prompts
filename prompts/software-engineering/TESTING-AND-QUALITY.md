# 🧪 测试与质量保障

此提示词集专注于自动化测试、Bug 诊断以及系统可靠性。

## 单元测试生成

### 提示词模板
```
请为以下代码编写高质量的单元测试：

待测代码：
[粘贴函数或组件代码]

测试要求：
- 测试框架：[如：Jest, Vitest, Pytest, JUnit]
- 覆盖率目标：应包含 正常路径、边界条件、异常情况。
- Mock 建议：如何 Mock 外部依赖（API 请求、数据库连接等）。
- 测试风格：[如：Given-When-Then]

请提供完整的测试文件代码。
```

## Bug 诊断与修复

### 提示词模板
```
我遇到了一个 Bug，请帮我分析原因并提供修复方案：

错误信息：
[粘贴堆栈信息或报错截图文字]

相关代码：
[提供可能相关的代码片段]

复现步骤：
[描述如何触发这个错误]

分析要求：
1. 根本原因分析 (Root Cause Analysis)：为什么会发生这个错误？
2. 修复代码：提供修正后的代码。
3. 防范措施：如何通过代码结构调整或静态检查来避免此类问题再次发生？
```

## 自动化测试策略设计

### 提示词模板
```
请为我们的项目设计完整的自动化测试策略：

项目简介：
[描述项目类型，如：高并发电商平台、内部管理系统]

技术栈：
[技术栈信息]

设计要求：
1. 测试金字塔分配：建议 单元测试、集成测试、E2E 测试的比例。
2. 工具链选型：推荐适合本项目的测试工具（如：Cypress, Playwright, K6）。
3. CI 流程集成：描述在流水线中何时运行何种测试。
4. 核心链路定义：列出最需要覆盖的 5-10 个关键业务流程。

请提供一份结构清晰的测试白皮书草案。
```

## 性能测试 (压力测试) 方案

### 提示词模板
```
我们需要对系统进行压力测试，请帮我设计方案：

测试目标：
[如：支撑 10,000 QPS / 验证自动扩缩容]

关键接口/操作：
[列出需要压测的环节]

方案要求：
1. 工具建议：(如：JMeter, k6, Locust)。
2. 场景模拟：如何模拟真实用户的流量行为。
3. 监控指标：压测期间应关注哪些核心指标（吞吐量、P99 延迟、资源利用率）。
4. 风险预案：如果压测导致系统崩溃，应如何快速恢复。

请提供详细的压测计划和脚本编写指南。
```

## 使用技巧

1. **先写测试，再写代码**：你可以利用 TDD 提示词，让 AI 先根据需求写出测试用例，再生成实现代码。
2. **边缘情况 (Edge Cases)**：在让 AI 写测试时，特别强调 "Think about edge cases like null, empty array, or network timeout"。
3. **结合覆盖率工具**：可以将生成的测试运行结果反馈给 AI，让它补齐未覆盖的部分。
